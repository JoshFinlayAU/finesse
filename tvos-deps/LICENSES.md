## Questions for the owner

1. **LGPL 3 and installation information.** This came with the owner's decision to use OpenSSL. LGPL 3 builds on GPL 3, and GPL 3 section 6 asks, for consumer products, for the "Installation Information" needed to install and run a modified version. An Apple TV is plausibly such a product. An App Store app can't be altered and re-signed by its user, and we don't control the signing system. LGPL 2.1 didn't have this clause, so it's a stricter position than before, and this is the main question for a lawyer. Other LGPL 3 apps on the App Store aren't evidence either way.
2. **Replacing the libraries.** LGPL section 4 of version 3, and section 6 of 2.1, are commonly met with a shared library mechanism that lets a user swap in a modified library. These frameworks are dynamic, which MPVKit's static link could not offer. Dynamic linking removes that problem without proving a user can really make the swap on a device, for the reason in question 1.
3. **Apache 2.0.** FFmpeg's `LICENSE.md` says Apache 2.0 is incompatible with LGPL 2.1 but not with version 3, which is why OpenSSL needs `--enable-version3`. mpv and libplacebo are LGPL 2.1 or later and link Apache-licensed MoltenVK as a separate dynamic library, and through FFmpeg they now sit beside OpenSSL. Reading them under version 3 looks like it resolves this, and it needs confirming.
4. **OpenSSL on Apple's SDK list.** Apple lists OpenSSL among the SDKs that need a privacy manifest and, when used as a binary dependency, a signature. Our framework has a manifest made from what it imports. We build it from source rather than taking a vendor binary, and it gets our team's signature when embedded in the app, so as we read it no vendor signature applies. This comes from reading Apple's rule rather than from an App Store upload, which hasn't been tried. Export compliance also changes: the app now bundles encryption, so the App Store encryption questions need answering for it.
5. **glslang's parser.** The Bison exception lets a parser generated by Bison be part of a larger work under any terms. The compiled parser is in Libplacebo. It looks fine and is here so nobody finds it by surprise.
6. **mpv's grant.** Upstream's statement quoted above means `-Dgpl=false` is a convenience rather than a promise. The `Copyright` file lists which files are GPL-only, and the build leaves them out.
7. **Patents.** Copyright licences say nothing about patents on codecs such as HEVC, DTS, TrueHD and Dolby. FFmpeg's decoders for these are included.

## What we'd have to ship, as we read it

- **Notices:** the full text of LGPL 3 and GPL 3, which LGPL 3 builds on, LGPL 2.1 for mpv, libplacebo and FriBidi, plus each permissive licence and copyright notice above, visible to the user. An in-app licences screen is the usual place, and the app doesn't have one yet.
- **FreeType's credit:** "Portions of this software are copyright (c) <year> The FreeType Project (www.freetype.org). All rights reserved."
- **Apache 2.0:** the licence text. We looked for `NOTICE` files at the top level of MoltenVK, SPIRV-Cross, SPIRV-Tools, Vulkan-Headers, cereal, Volk and OpenSSL and found none, so there is none to reproduce from those.
- **Source:** for each LGPL component, the exact source and our patches. Either ship it alongside or include a written offer valid for three years. Hosting it next to each app release from a server we control is the simple route. `versions.sh`, `checksums.sha256`, `patches/` and these scripts are what someone needs to rebuild.
- **How to replace them:** written instructions for building a replacement framework with these scripts and putting it in the app, which for LGPL 3 is also where Installation Information would go. See questions 1 and 2 for how far that really works.
- **A statement in the app** that it uses these libraries and that they are under the LGPL.
- **Our own licence choice:** the app's licence is undecided, and LGPL section 6 also limits terms that forbid reverse engineering for debugging such changes. That belongs in whatever terms the app ships with.
